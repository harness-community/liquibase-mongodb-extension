# AGENTS.md - MongoDB Statements

## Purpose

This package contains **MongoDB statement implementations** that represent low-level database operations. Statements are generated by change types and executed by executors.

In Liquibase's architecture:
- **Change types** (user-facing) → generate → **Statements** (internal) → executed by → **Executors**

Statements encapsulate the actual MongoDB Java Driver API calls and operation logic.

## Key Files

### Base Classes
- **`AbstractMongoStatement.java`** - Base class for all MongoDB statements
  - Provides common functionality for MongoDB operations
- **`AbstractCollectionStatement.java`** - Base for collection-scoped operations
  - Handles collection name validation and retrieval
- **`AbstractRunCommandStatement.java`** - Base for command execution statements
  - Common logic for runCommand and adminCommand operations

### Collection Operations
- **`CreateCollectionStatement.java`** - Create MongoDB collections
- **`DropCollectionStatement.java`** - Drop single collection
- **`DropAllCollectionsStatement.java`** - Drop all collections in database
- **`ListCollectionNamesStatement.java`** - List all collection names
- **`CountCollectionByNameStatement.java`** - Count collections matching name

### Index Operations
- **`CreateIndexStatement.java`** - Create indexes with options
- **`DropIndexStatement.java`** - Drop indexes by name or keys

### Document Operations
- **`InsertOneStatement.java`** - Insert single document
- **`InsertManyStatement.java`** - Insert multiple documents
- **`FindAllStatement.java`** - Find all documents in collection
- **`FindOneAndUpdateStatement.java`** - Atomic find and update
- **`UpdateManyStatement.java`** - Update multiple documents
- **`DeleteManyStatement.java`** - Delete multiple documents
- **`CountDocumentsInCollectionStatement.java`** - Count documents matching filter

### Command Execution
- **`RunCommandStatement.java`** - Execute database commands
- **`AdminCommandStatement.java`** - Execute admin commands
- **`MongoshStatement.java`** - Execute mongosh shell commands (Harness enhancement)

### Utilities
- **`BsonUtils.java`** - BSON utility methods for converting between JSON and BSON

## Testing

- **Run tests for this package**: `mvn test -Dtest=*StatementTest`
- **Test file pattern**: `*Statement.java` → `*StatementTest.java` in `src/test/java/liquibase/ext/mongodb/statement/`
- **Note**: Most statement classes don't have dedicated unit tests - they're tested via change type tests and integration tests

## Important Patterns

### Statement Interface
All statements implement Liquibase's `SqlStatement` interface (despite being NoSQL):
```java
public class InsertOneStatement extends AbstractCollectionStatement {
    // MongoDB-specific implementation
}
```

### MongoDB Connection Access
Statements receive `MongoConnection` from executors and use MongoDB Java Driver directly:
```java
MongoDatabase database = connection.getMongoDatabase();
MongoCollection<Document> collection = database.getCollection(collectionName);
collection.insertOne(Document.parse(document));
```

### BSON Conversion
Use `BsonUtils` for JSON ↔ BSON conversions:
```java
Document doc = BsonUtils.orEmptyDocument(jsonString);
```

### Collection Name Resolution
Collection-scoped statements extend `AbstractCollectionStatement`:
```java
protected String getCollectionName() {
    return StringUtils.trimToEmpty(collectionName);
}
```

## DOs

- Extend appropriate abstract base class (`AbstractMongoStatement`, `AbstractCollectionStatement`, `AbstractRunCommandStatement`)
- Use MongoDB Java Driver API directly for operations
- Use `BsonUtils` for JSON/BSON conversion
- Add `@Getter` and `@Setter` Lombok annotations for properties
- Implement `toString()` for debugging and logging
- Keep statements focused on single operation - compose in change types if needed
- Use `MongoConnection` to access MongoDB database and collections
- Handle BSON Document parsing safely with error checking

## DON'Ts

- Don't add business logic in statements - keep them focused on MongoDB API calls
- Don't modify base classes without understanding impact on all subclasses (21 statement files!)
- Don't mix MongoDB Java Driver versions - stick to 4.10.2
- Don't perform validation in statements - validation belongs in change types
- Don't log sensitive data (credentials, document contents) in toString() methods
- Don't throw generic exceptions - use Liquibase exception types where appropriate
- Don't add Liquibase changelog manipulation logic - statements are for execution only

## Architecture Notes

**Why so many statement classes?**
- Each MongoDB operation has its own statement class for type safety and clarity
- Follows Liquibase's pattern of one statement type per operation
- Makes testing and debugging easier (can test statements independently)

**BsonUtils importance:**
- Centralizes JSON ↔ BSON conversion logic
- Handles parsing errors consistently
- Provides default/empty document handling

**Recent focus:**
- MongoshStatement for native mongosh command execution
- Minimal changes to other statements (stable API)
